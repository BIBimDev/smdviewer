# GEO-Visualiser — first native inspection milestone

## Scope and baseline

Task branch: `feat/geo-visualiser`. Fetched `origin` before editing on
2026-11-13: `main`, HEAD and `origin/main` all matched the accepted GEO-03
commit `b999943acfe1c70f62c6fd7fc349018a7ab850e1`. Pre-existing untracked
`.vscode/` is excluded. The PR is for review, not merge.

This opt-in C++20 application uses Qt 6 Widgets and OCCT AIS/OpenGL. Changes
are confined to `geo-visualiser/`, root/geometry CMake integration, and this
document. Qualified parser/geometry algorithms, fixtures, browser viewer and
WASM integration are unchanged. `tsconfig.tsbuildinfo` remains tracked and
unchanged after restoring the artifact regenerated by the browser build.

## Operator note

Launch the generated Windows wrapper from **any current directory**:

```powershell
& 'C:/smdviewer/build/visualiser-windows/geo-visualiser/Release/start-geo-visualiser.cmd'
```

It sets process-local OCCT/Qt DLL paths and the Qt platform plugin path, then
starts `geo-visualiser.exe`. It neither installs dependencies globally nor
changes the caller's environment. Keep the configured dependency installations
available. MSVC's x64 runtime must also be available (present on the tested
Build Tools machine); a portable installer/runtime deployment is not delivered.

The Specimen dropdown contains exactly:

| Label | Original repository file |
| --- | --- |
| Plain column | `public/samples/plain_column.smd` |
| Combined pocket/corbel column | `public/samples/SinglePocketingSingleCorbelColumn.smd` |

The fixture directory is captured as an **absolute source checkout path by
CMake** in a generated header. Original files are read directly, not copied or
embedded. The combined filename contains no space before `.smd`. Reconfigure
after moving the checkout; missing files produce a visible diagnostic and no
results. There is no File Open or general import facility.

The initial view is plain-column **validated solid S**. Choose Converted faces,
S, B, A or R with Representation; only that representation is displayed.
Converted faces are explicitly a collection, never presented as a solid.
Isolate selects an individual source face or body; All restores the group.
Empty A/R groups are shown explicitly and leave an empty viewport. R is a
positive body displaying missing material. There is no reconstructed S' view.

- Left drag orbits; right/middle drag pans; wheel zooms; Fit adjusts the camera.
  Resizing the native drawable also fits the visible geometry.
- Vertex, Edge, Face and Body activate exclusive OCCT topological pick modes.
  Body applies to solid representations; the converted face collection has no
  selectable body. Selecting an entity in the tree sets its corresponding mode.
- A click and a tree selection share one selected AIS owner, highlighted yellow.
  Changing representation, specimen, isolation or pick mode clears selection.
  Removed components are also removed from the OCCT selector.
- Metadata shows raw source-local millimetres and zero-based source ordinals.
  No B-rep, element or project placement is applied, and no shape is recentered.
- Select an entity, enter a tag and press Add / rename (or Enter); Remove deletes
  it. Tags survive specimen switches in the same window/run. Restart clears
  them. They are not source names, source identities or geometry edits.

## Evidence and display architecture

The loader calls `parseSmd10125`, `convertFaces`, `assembleShell`, `buildSolid`,
`buildPrincipalPrismCandidate`, and `decomposeBoolean` in process. No extractor,
JSON round-trip, alternate algorithms, healing, or tolerance adjustment is used.
A document is published only after the entire pipeline succeeds. Missing or
unsupported input reports the file and failing stage; no partial conversion is
exposed as validated. A graphics failure hides the viewport and clears results.

The immutable document owns parsed evidence and every original pipeline result.
The display adapter uses `BRepBuilderAPI_Copy(shape, true, false)` for private
topology, curves and surfaces, without sharing input meshes. Its explicit
`ModifiedShape` correspondence maps original vertices/edges/faces/bodies to the
copies handed to AIS. Only copies are tessellated or selected. Fit/navigation
changes the camera. The existing kernel tolerance policies remain unchanged.

Identity is deliberately separated:

| Information | Meaning |
| --- | --- |
| Direct source identity | Known GEO-01/GEO-02 handle correspondence, never proximity matching |
| Converted edge | One face/loop occurrence; coincident occurrences retain different IDs and topology |
| S edge | The established shared edge, source endpoint ordinals, and both source loop uses |
| B support | Candidate-level supporting source face only; no per-face source identity inferred |
| A/R face lineage | Every recorded Boolean ancestor with source/candidate/unknown origin and unchanged/modified/generated/removed/unknown classification |
| Viewer ID | `specimen/representation/component/kind/entity`, zero-based local indices; session scope, not durable source identity |
| User tag | Session-only string keyed by viewer ID, stored separately from geometry and lineage |

Known source face names, flags, ordered loops, plane coefficients and the B-rep
token identity remain accessible in metadata. Source-origin Boolean ancestors
show the corresponding source metadata as ancestry. Unknown identities are
reported explicitly; no ancestry is invented from coincidence. The supporting
source face of B does not become an ancestor of every B face. Geometry and
source evidence persistence are outside this milestone.

The fixture results are **sample-verified**, not general STRAKON/DICAD rules.
Candidate B is a derived interpretation, not established mould intent or a
recovered manufacturing history.

## Windows dependency build

Tested toolchain: Windows x64, MSVC 19.44.35230.0 / MSBuild 17.14.60,
Windows SDK 10.0.26100.0, CMake 3.31.6-msvc6, Python 3.14.6, Qt **6.8.3**
`win64_msvc2022_64`. Qt 6 Widgets is discovered only with the viewer option.
The build currently requests Qt >=6.2; only 6.8.3 was tested.

Exact OCCT **8.0.1**, without development suffix, source tag `V8_0_1`, commit
`b8f597c677811d1f9f4d8a97f5ae2825c0353a42`. The separate visualization install
uses C++20, Release shared libraries, TBB OFF, FreeType OFF, and the
TKBO/TKPrim/TKOpenGl/TKV3d dependency closure (including TKService/TKMesh).
Text is rendered by Qt; no OCCT text overlay requires FreeType. The prior
headless installation was not changed. This does not change the kernel pin.

Commands below were run in PowerShell from `C:/smdviewer`; command failures
were checked before continuing. Build directories were initially unused.
Logs are retained locally under ignored `build/visualiser-*.log` and CTest's
`Testing/Temporary/LastTest.log`.

```powershell
$taskCmake = 'C:/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe'
$taskCtest = Join-Path (Split-Path $taskCmake) ctest.exe
$taskOcctSource = "$env:TEMP/smdviewer-geo01a-cf8fa7d-20261113/occt-source"
$taskHeadless = "$env:TEMP/smdviewer-geo01a-cf8fa7d-20261113/occt-install"
$taskVisual = 'C:/smdviewer/build/geo-visualiser-deps/occt-install'
$taskQt = 'C:/smdviewer/build/geo-visualiser-deps/Qt/6.8.3/msvc2022_64'

# Reuse the verified source checkout, with a NEW build and install prefix.
git -C $taskOcctSource rev-parse HEAD
& $taskCmake -S $taskOcctSource -B build/geo-visualiser-deps/occt-build `
  -G 'Visual Studio 17 2022' -A x64 `
  -DBUILD_CPP_STANDARD=C++20 -DBUILD_LIBRARY_TYPE=Shared `
  -DBUILD_MODULE_FoundationClasses=OFF -DBUILD_MODULE_ModelingData=OFF `
  -DBUILD_MODULE_ModelingAlgorithms=OFF -DBUILD_MODULE_Visualization=OFF `
  -DBUILD_MODULE_ApplicationFramework=OFF -DBUILD_MODULE_DataExchange=OFF `
  -DBUILD_MODULE_Draw=OFF '-DBUILD_ADDITIONAL_TOOLKITS=TKBO;TKPrim;TKOpenGl;TKV3d' `
  -DUSE_TBB=OFF -DUSE_FREETYPE=OFF -DUSE_TK=OFF "-DINSTALL_DIR=$taskVisual"
& $taskCmake --build build/geo-visualiser-deps/occt-build --config Release --parallel 6
& $taskCmake --install build/geo-visualiser-deps/occt-build --config Release

# Isolated Qt download tools and official Qt binary archives; no global install.
C:/Python314/python.exe -m venv build/geo-visualiser-tools
& build/geo-visualiser-tools/Scripts/python.exe -m pip install aqtinstall==3.3.0
& build/geo-visualiser-tools/Scripts/python.exe -m aqt install-qt `
  windows desktop 6.8.3 win64_msvc2022_64 `
  -O C:/smdviewer/build/geo-visualiser-deps/Qt --archives qtbase qttools
```

Qt's MSVC package policy is described in
[Qt's MSVC 2022 announcement](https://www.qt.io/blog/moving-to-msvc-2022-in-qt-68).
The [OCCT copy API](https://www.occt3d.com/dev/doc/refman/html/class_b_rep_builder_a_p_i___copy.html)
documents the geometry/mesh-copy controls; implementation was also checked
against the exact local 8.0.1 source and headers.

## Acceptance evidence

| Specimen | Converted faces | S vertices / edges / faces | B supporting source face | A | R |
| --- | ---: | --- | ---: | --- | --- |
| Plain | 6 | 8 / 12 / 6 | 1 | Empty | Empty |
| Original combined | 14 | 24 / 36 / 14 | 5 | One, 15,000,000 mm³ | One, approximately 42,614,000.00009004 mm³ |

A and R are independently compared against the arithmetic references in
[GEO-03C](GEO-03C.md), each with **1 mm³ absolute tolerance**. The test never
substitutes a net `V(S)-V(B)` comparison for either reference.

Automated checks cover private display topology/surfaces/curves, exact
copy-to-original mappings and coordinates, all known direct source identities,
24/72 distinct converted edge occurrences versus 12/36 shared S edges,
candidate ancestry separation, complete Boolean lineage (including an explicitly
synthetic multi-contributor ledger), session tags, missing fixtures, and failed
face/shell pipeline stages. The unchanged kernel suites cover their further
stage rejections and malformed inputs.

Preservation snapshots include parser JSON plus bitwise B-rep evidence, original
BREP serialization, recursive topology identities/orientations/flags, source
correspondence and reversal history, candidate metadata, Boolean output shapes
and recorded histories. They are compared before/after display preparation and
after actual AIS rendering, picking and camera navigation. Test snapshots are
diagnostics, not a proposed persistence contract.

## Manual remote-desktop acceptance — pending

Run through the user's **normal remote desktop connection**, not a local console
or just a process launch. Record Windows version, remote client/protocol,
display scaling, graphics driver, branch/commit, and pass/fail notes:

1. Launch the wrapper above from a different working directory. Confirm the
   full viewport displays plain S, fills the available panel after resizing,
   and repaints after minimizing/restoring. Orbit, pan, zoom and Fit.
2. Pick a visible vertex, edge, face and body. For each mode, confirm one yellow
   highlight, matching tree item and metadata. Select tree entities and confirm
   the corresponding viewport highlight. Clicking background clears selection.
3. Switch to Converted faces, isolate a face, and exercise vertex/edge/face
   selection. Confirm that other faces cannot intercept picks. Body selection
   must not pretend this collection is a solid.
4. Switch specimens and representations. Confirm plain A/R are empty; combined
   A and R each contain one isolatable body and show their separate volumes.
   Inspect their face ancestor lists. R must be described as missing material.
5. Add a tag on an S face; a coincident B face must have no such tag. Switch
   specimens and back: the S tag remains. Rename/remove it. Add another tag,
   close the application, restart, and confirm it is gone.
6. Confirm selection clears on representation/specimen/isolation changes,
   and test the same interactions at the normal remote display scaling.

A build, captured framebuffer, programmatic hit-test or local-desktop smoke
does **not** establish remote-desktop operation. This checkbox remains pending
until an operator performs the above through that connection.
